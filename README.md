# works-on-my-claude v4.0.0

코딩을 몰라도 Claude Code 가 꾸준히 잘 일하게 만드는 **얇은 기본 하네스**를 프로젝트에 깐다. 설치하면 끝이다. `/womc` 를 칠 일도 거의 없다.

## 철학
하네스는 얇게, 나머지는 모델을 믿고 맡긴다. 사용자가 승인하거나 결정하는 일을 최소로 줄인다.
하네스 기능은 그때 모델의 약점을 덮는 임시 장치다. 모델이 좋아지면 뺀다.

## 설치
```
/plugin marketplace add yeejh96-bit/works-on-my-claude
/plugin install womc@works-on-my-claude
```
그 다음 아무 프로젝트 폴더에서 `claude` 를 열면 된다.

## 어떻게 돌아가나
1. 세션이 시작될 때 플러그인 훅이 폴더를 본다. womc 세팅이 없거나 낡았으면 모델에게 알린다.
2. 모델이 첫 대화에서 묻지 않고 세팅한다. 파일은 넷뿐이다.
   - `CLAUDE.md` — 작업 규칙(약 50줄) + 브리핑. 200줄을 넘기지 않는다.
   - `.claude/settings.json` — 권한. 파일 수정·git·실행은 허용, `git push` · `git reset --hard` · 지우기 · 옮기기만 묻고, `.env` 는 읽기 차단.
   - `.claude/statusline.js` — 터미널 아래 한 줄(모델·토큰·폴더명).
   - `.gitignore` — 없을 때만.
3. 브리핑은 모델이 채운다. 폴더를 읽고 코드로 알 수 없는 것만 묻는다. 빈 폴더면 「무엇을 만들 건가」 한 가지, 코드가 있으면 보통 아무것도 안 묻는다.
4. 사용자가 그 뒤에 한 말(지킬 것 · 끝난 조건 · 확인 명령)은 모델이 브리핑으로 옮기고, 브리핑에 맞춰 규칙·권한을 스스로 고친다.
5. 기능 작업은 「쪼개기 → 체크포인트 커밋 → 구현 → 별도 서브에이전트가 확인 → 결과를 붙여 한 줄 보고」 순서로 한다. 한 세션에 안 끝날 일만 `TASKS.md` 에 적고 끝나면 지운다.

기존 프로젝트나 옛 womc(v3 이하) 프로젝트도 같다. 모델이 기존 하네스를 읽어 코드로 알 수 없는 사실만 남기고 v4 모양으로 새로 쓴다. 지우기 전에 커밋을 남기므로 묻지 않는다.

승인 창을 더 줄이려면 Claude Code 의 auto mode 를 켜면 된다. 그러면 위의 「묻는 4가지」만 남는다.

## 플러그인 안에 있는 것
```
skills/womc/SKILL.md       세팅·다시 짜기 절차 + 정본(CLAUDE.md · settings.json · .gitignore)
hooks/hooks.json           세션 시작 훅
scripts/womc-check.js      세팅 유무·버전 검사
templates/statusline.js    상태줄
scripts/bump-version.py    버전 한 번에 올리기(개발용)
```
서브에이전트·절차 스킬은 주지 않는다. Claude Code 내장 에이전트로 충분하다.

## 안 만드는 것
- `.mcp.json` 자동 생성 — 프로젝트마다 달라 필요할 때 직접 더한다.
- 기술 스택·기능을 골격에 미리 박기 — 빈 틀만 둔다.
- `/womc` 가 코드를 구현하기 — 세팅까지만.
- GUI.

## v4.0.0 에서 바뀐 것
- `/womc` 를 치지 않아도 세션 시작 훅이 세팅·갱신을 알아서 시작한다.
- 서브에이전트 4종 · 스킬 3종 · `PLAN.md` · `docs/CHANGELOG.md` · 온보딩 6단계 · `update` · `eject` · 검사기 · git 훅을 뺐다.
- 사용자에게 묻는 지점 9곳을 되돌릴 수 없는 4가지로 줄였다.
- 기존 프로젝트는 덧붙이지 않고 v4 모양으로 새로 짠다.
