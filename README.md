# works-on-my-claude v4.5.0

코딩을 몰라도 무엇을 원하는지만 말하면 Claude Code 가 나머지를 맡게 만드는 **얇은 기본 하네스**를 프로젝트에 깐다. 설치하면 끝이다. `/womc` 를 칠 일도 거의 없다.

## 철학
사람은 무엇을 원하는지와 되돌릴 수 없는 결정만 맡는다. 되묻기·계획·구현·검증은 모델이 맡는다.
그래서 하네스는 얇다. 사용자가 승인하거나 결정하는 일을 최소로 줄이고, 모델이 좋아질수록 더 얇아진다.

## 설치
```
/plugin marketplace add yeejh96-bit/works-on-my-claude
/plugin install womc@works-on-my-claude
```
그 다음 아무 프로젝트 폴더에서 `claude` 를 열면 된다.

## 어떻게 돌아가나
1. 세션이 시작될 때 플러그인 훅이 폴더를 본다. womc 세팅이 없거나 낡았으면 모델에게 알린다.
2. 모델이 첫 대화에서 묻지 않고 세팅한다. 파일은 넷뿐이다.
   - `CLAUDE.md` — 작업 규칙(약 50줄) + 브리핑. 200줄을 넘기지 않는다.
   - `.claude/settings.json` — 권한. 파일 수정·git·실행은 허용, `git push` · `git reset --hard` · 지우기 · 옮기기만 묻고, `.env` 는 읽기 차단.
   - `.claude/statusline.js` — 터미널 아래 한 줄(모델·토큰·폴더명).
   - `.gitignore` — 없을 때만.
3. 브리핑은 모델이 채운다. 폴더를 읽고 코드로 알 수 없는 것만 묻는다. 빈 폴더면 「무엇을 만들 건가」 한 가지, 코드가 있으면 보통 아무것도 안 묻는다.
4. 사용자가 그 뒤에 한 말(지킬 것 · 끝난 조건 · 확인 명령)은 모델이 브리핑으로 옮기고, 브리핑에 맞춰 규칙·권한을 스스로 고친다.
5. 기능 작업은 「모호하면 되묻기 → 무엇을 만들지 다섯 줄로 보여 주기 → 쪼개기 → 체크포인트 커밋 → 구현 → 요청 전체가 끝났을 때 별도 서브에이전트가 딱 한 번 확인 → 결과를 붙여 한 줄 보고」 순서로 한다. 이 순서는 요청 하나에 한 번만 돌고, 세부 단계마다 다시 돌지 않는다. 이번 세션에 못 끝내는 단계만 `TASKS.md` 에 적고 끝나면 지운다.

기존 프로젝트나 옛 womc(v3 이하) 프로젝트도 같다. 모델이 기존 하네스를 읽어 코드로 알 수 없는 사실만 남기고 v4 모양으로 새로 쓴다. 지우기 전에 커밋을 남기므로 묻지 않는다.

승인 창을 더 줄이려면 Claude Code 의 auto mode 를 켜면 된다. 그러면 되돌릴 수 없는 것만 묻는다.

## 플러그인 안에 있는 것
```
skills/womc/SKILL.md       세팅·다시 짜기 절차 + 정본(CLAUDE.md · settings.json · .gitignore)
hooks/hooks.json           세션 시작 훅
scripts/womc-check.js      세팅 유무·버전 검사
templates/statusline.js    상태줄
scripts/bump-version.py    버전 한 번에 올리기(개발용)
```
서브에이전트·절차 스킬은 주지 않는다. Claude Code 내장 에이전트로 충분하다.

## 안 만드는 것
- `.mcp.json` 자동 생성 — 프로젝트마다 달라 필요할 때 직접 더한다.
- 기술 스택·기능을 골격에 미리 박기 — 빈 틀만 둔다.
- `/womc` 가 코드를 구현하기 — 세팅까지만.
- GUI.

## v4.3.3 에서 바뀐 것
- 브리핑·.claude/rules 에 무엇을 적을지 기준을 넣었다. 「이 줄이 없으면 다음 작업이 달라지나」를 묻고, 의향·계획·사정(예: 유료화할 생각이 있다)·진행 기록은 적지 않는다. 지시로 쓸 수 있는 것만 「…한다/…하지 않는다」 꼴로 적는다.
- 세션 시작 정리와 「다시 짜기」에서 기준에 안 맞는 줄을 지운다.

## v4.3.1 에서 바뀐 것
- 검증 서브에이전트를 값싸게 부르게 했다. 돌릴 명령·기대 출력·바뀐 파일 목록·답 형식을 프롬프트에 다 적어 재탐색을 막고, 모델은 작은 것(haiku·sonnet)으로 지정한다.
- 서브에이전트를 부를 때 일의 수준을 모델이 판단해 가장 작은 모델을 고르고, 애매하면 한 단계 올린다.
- 브리핑의 확인 방법은 「명령 한 줄 + 기대 출력 한 줄」로 적는다. 사람 눈으로만 아는 것은 명령 대신 화면으로 확인한다.

## v4.2.3 에서 바뀐 것
- 카파시 원칙 둘을 「일하는 방식」에 넣었다. 제품 코드에 아직 없는 문제용 기능을 미리 만들지 않고, 맡긴 일 밖의 코드는 손대지 않는다.
- 일하다 알게 된 틀린 가정·안 되는 도구·프로젝트만의 사실은 사용자가 말하지 않아도 브리핑이나 rules 에 남긴다.

## v4.2.2 에서 바뀐 것
- 검증 서브에이전트를 세부 단계(1-1, 1-2)마다 부르던 것을 막았다. 작업 순서 자체가 요청 하나에 한 번만 도는 것임을 제목에 못 박았다.
- 구현 중 「진행 확인」(빌드·테스트가 안 깨졌나)과 마지막 「검증」을 갈랐다. 검증은 언제나 별도 서브에이전트가 하고, 만든 쪽이 스스로 판정하지 않는다.

## v4.1.0 에서 바뀐 것
- 철학을 「사람은 원하는 것과 되돌릴 수 없는 결정만, 나머지는 모델이」로 바꿨다.
- 기능 작업 순서에 「모호하면 되묻기 → 무엇을 만들지 다섯 줄로 보여 주기」를 앞에 붙였다. 단계는 채팅에 보여 주고 `TASKS.md` 에는 못 끝낸 것만 적는다.
- 묻는 항목을 숫자로 못 박지 않고 「커밋으로도 못 되돌리는 것」 기준과 예시로 두었다.

## v4.0.0 에서 바뀐 것
- `/womc` 를 치지 않아도 세션 시작 훅이 세팅·갱신을 알아서 시작한다.
- 서브에이전트 4종 · 스킬 3종 · `PLAN.md` · `docs/CHANGELOG.md` · 온보딩 6단계 · `update` · `eject` · 검사기 · git 훅을 뺐다.
- 사용자에게 묻는 지점 9곳을 되돌릴 수 없는 4가지로 줄였다.
- 기존 프로젝트는 덧붙이지 않고 v4 모양으로 새로 짠다.
