골격(`CLAUDE.md`·명령·에이전트·스킬·설정)을 설계하거나 고칠 때만 켜지는 제약이다 — 위 `paths` 가 그때만 부른다. 그래도 짧게 유지한다.
`paths` 가 붙어 있어 **서브에이전트에는 자동으로 전달되지 않는다** — 위임할 때 메인이 이 파일을 읽어 필요한 항목을 프롬프트 본문에 붙여 넣는다(정본은 `CLAUDE.md` 「적극 위임」).
**아래 항목의 전문(경위·근거·다시 열 조건)은 `docs/CHANGELOG.md` 에 있다** — 2026-08-28 이전 것은 「닫힌 결정·안 고른 길 (전문)」 절(그날 얼린 스냅샷)에, 그 뒤 것은 각 버전 항목에. 여기엔 결론만 둔다.

**나가는 문**(안 두면 판올림마다 쌓이기만 한다): 어떤 항목을 다시 하자는 제안이 골격 버전 세 판 동안 한 번도 안 나왔으면 그 항목을 뺀다. 가리키는 대상 자체가 골격에서 이미 사라진 항목도 같은 방식으로 뺀다.
뺄 때 `docs/CHANGELOG.md` 에 무엇을·언제·왜 뺐는지 한 줄 남긴다 — 나중에 같은 제안이 다시 나오면 되살릴 근거가 된다. 다만 「다시 만들지 마라」로 아직 살아 있는 제약은 대상이 없어져도 빼지 않는다.

## 사용자가 닫은 것
- **서브에이전트 4종은 `tools:` 에 `Skill` 을 갖는다** (v3.9.0, 2026-09-01). 화이트리스트에서 `Skill` 을 다시 빼지 않는다 — 빼면 스킬 호출은 물론 **스킬 목록 주입 자체가 끊긴다**(실측으로 확인). 서브에이전트가 쓰는 범위(`.claude/skills/` 프로젝트 스킬까지, `womc:` 절차 스킬은 제외)의 정본은 `CLAUDE.md` 「프로젝트 스킬·규칙」 세 번째 불릿 한 줄이다 — 에이전트 본문에 베껴 적지 않는다.
- **하네스 감사는 사용자가 부를 때만 돈다 — `/womc update` 가 자동으로 부르지 않는다** (v2.1.0 → v3.8.0, 2026-09-01). 감사는 웹 조사가 들어가 골격에서 가장 무겁고, v3.7.0 이 트리거를 전체 버전 비교로 넓힌 뒤로는 갱신할 때마다 돌았다. `/womc update` 7번은 **안내 한 줄 + 열린 확인 알림**만 한다(되묻기도 없다). 다시 자동 호출로 되돌리지 않는다. 다시 열 조건: 사용자가 안내를 보고도 감사를 안 불러 골격이 눈에 띄게 낡는 일이 두 번 이상 쌓이면.
- **이 파일은 always-on 이 아니다 — 골격을 설계·수정할 때만 켜진다** (v3.6.0, 2026-08-31). 설계할 때만 쓸모 있는 기록(예전에 버린 대안을 다시 꺼내지 않게 막는 것)이 모든 순간에 읽히고 있었다 — 6,102자로, 매 세션 읽히던 것의 67%였다. `paths` 로 내리고, 설계 전에는 `plan-feature` 가 읽는다. 다시 열 조건: 이미 뺀 대안을 다시 제안하는 일이 두 번 이상 나오면 `paths` 를 떼고 always-on 으로 되돌린다.
- **모델을 믿는다 — 일과 서브에이전트를 짝지어 주지 않는다** (v3.2.0 → v3.4.0, 2026-08-31). v3.2.0 은 절 번호·서브에이전트 이름 지정을 `plan-feature` 에서 빼고 정본을 `CLAUDE.md` 「적극 위임」에 뒀고, **v3.4.0 은 그 정본 자리에서도 뺐다** — 각 서브에이전트가 자기 `description` 에 「언제 쓰는지」를 이미 적어 두어 같은 사실이 두 곳이었고, 철학(순서도, 어느 에이전트를 쓸지도 지시하지 않는다)과 정면으로 어긋났다. 「조사는 explore, 설계는 plan」 같은 지정을 스킬에도 `CLAUDE.md` 에도 다시 박지 않는다. 다시 열 조건: 위임이 엉뚱한 에이전트로 가는 일이 두 번 이상 쌓이면.
- **열린 확인을 「트리거가 없어도」 붙잡아 두지 않는다** (v3.4.0, 2026-08-31). 확인할 방법이나 계기가 없는 관찰 항목은 `TASKS.md` 에서 지우고, 같은 일이 다시 걸리면 그때 되살린다 — 미리 예측해 남기지 않는다.
- **`scripts/check-sync.py` 6번(결합 대조)은 횟수를 세지 않고 존재 여부만 본다** (v3.4.0, 2026-08-31). 문장을 줄일 때마다 스크립트의 숫자를 따라 내려야 해서 「지우고 써 본다」에 비용을 매기고 있었다. 결합이 **끊기는 것**(이름이 아예 사라지는 것)은 계속 잡되 횟수는 안 센다. 다시 열 조건: 이름은 남았는데 뜻이 끊긴 사고가 실제로 나면.
- **`CLAUDE.md` 에 이미 있는 것을 `plan-feature` 에 다시 적지 않는다** (v3.2.0, 2026-08-31). 그래서 범위 확인(「안 만들 것」)·`/code-review` 권유·체크포인트 커밋·새 세션 권유 절을 스킬에서 뺐다.
