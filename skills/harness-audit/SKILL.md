# 하네스 감사하기

Claude Code 가 새 버전에서 기본 제공하게 된 기능을 골격이 계속 손으로 떠안고 있으면 토큰만 먹고 사실관계가 어긋난다.
`/womc update` 는 "womc 최신판"을 가져올 뿐이라, Claude Code 최신 기능에 맞춰 골격을 줄이는 판단은 이 스킬이 맡는다.
`/womc update` 의 마지막 단계가 이 스킬을 자동으로 부르므로, 사용자가 따로 부르지 않아도 갱신 뒤에 한 번 돌아간다.

## 1. 지금 버전과 지난 감사 확인
- `claude --version` 으로 현재 Claude Code 버전을 알아낸다. (실행이 막히면 사용자에게 `claude --version` 을 쳐 달라고 한 줄로 부탁한다.)
- `docs/HARNESS-AUDIT.md` 를 읽어 **마지막 감사 기준 버전**을 확인하고, 파일 머리의 `womc:open-checks` 구획을 읽어 **열린 확인 목록(`open:...`)** 을 파악한다.
  각 항목의 전문(조건·확인 방법)은 `TASKS.md` 「할 일」에 있다 — 상세가 필요하면 그쪽을 읽는다.
  파일이 없으면 이번이 첫 감사다 — 6단계에서 새로 만든다.
- 두 버전이 같으면 "지난 감사 이후 Claude Code 가 안 올라갔다"고 알리고 **멈춘다**(사용자가 그래도 하자면 진행).
  **멈추기 전에 열린 확인 목록을 한 줄씩 사용자에게 알린다**(무엇이 아직 안 닫혔는지). 목록이 비어 있을 때만 조용히 멈춘다.

## 2. 그 사이 무엇이 바뀌었나 조사 (웹은 general-purpose, 로컬은 explore)
지난 감사 버전 ~ 현재 버전 사이의 변경을 조사한다. 갈래를 도구에 맞게 나눠 **한 메시지에서 여러 개를 병렬로** 띄운다.
- **웹 갈래**(공식 문서 `code.claude.com/docs/en/*`, CHANGELOG·릴리스 노트)는 내장 `general-purpose` 에 그 자리에서 프롬프트를 짜서 위임한다.
  `explore`(`agents/explore.md`)의 `tools` 는 `Read, Grep, Glob` 뿐이라 웹을 못 본다 — 시키면 「확인 못 함」으로 돌아오거나 URL 을 지어낼 수 있다.
  `CLAUDE.md` 「적극 위임」의 "4종에 안 맞으면 `general-purpose` 에 즉석 위임" 규칙을 따른 것이다.
- **로컬 갈래**(이 프로젝트가 무엇을 손으로 떠안고 있는지)만 `explore` 에 맡긴다.
  - 이 프로젝트 안: `CLAUDE.md`·`SPEC.md`·`HARNESS.md`·`.claude/settings.json`·`.claude/statusline.js`·`.claude/rules/`.
  - 플러그인이 제공하는 정의(프로젝트 밖): `agents/`·`skills/`·`output-styles/`·`commands/womc.md` — Windows `C:\Users\<사용자>\.claude\plugins\marketplaces\works-on-my-claude\`, mac·linux `~/.claude/plugins/marketplaces/works-on-my-claude/` 아래(`commands/womc.md` 꺼내기 모드 절과 같은 경로).
  - 여기가 womc 저장소 자신이면(저장소 루트에 `agents/`·`skills/`·`commands/womc.md` 가 바로 있으면) 그쪽을 본다.

**모든 결론에는 근거 URL 이나 `파일경로:줄번호` 를 붙이게 한다. 근거 URL 을 가져오지 못했으면 그 항목은 「실측 필요」다 — 지어내지 마라.**

## 3. 골격 항목을 하나씩 대조
골격이 제공하는 것을 목록으로 늘어놓고, 각각에 대해 **"이제 Claude Code 기본으로 되는가"** 를 판정한다. 판정은 셋뿐이다:
- **뺄 수 있음** — 공식 문서에 명시된 근거 URL 이 있다.
- **남길 것** — 기본으로 안 되거나, 되더라도 남겨야 할 이유가 있다. **그 이유를 적는다.**
- **실측 필요** — 문서에 명시가 없다. 추측으로 「뺄 수 있음」에 넣지 마라.

**지난 기록이 사실로 적어 둔 전제도 다시 의심한다.** 이 스킬의 가장 큰 값은 "예전엔 맞았지만 지금은 거짓인 전제"를 잡는 것이다
(실제 사례: v1.19.0 이 "커스텀 서브에이전트는 CLAUDE.md 를 안 물려받는다"고 기록했으나 Claude Code 2.1.224 에서 거짓이었고,
그 한 문장이 보일러플레이트 100줄을 지탱하고 있었다). 뒤집힌 전제를 찾으면 별도로 표시한다.

## 4. 보고
사용자에게 **근거 URL 과 함께** 세 묶음으로 보고한다: 뺄 수 있는 것 / 남길 것(이유) / 실측 필요.
사용자는 코딩을 모른다 — "이걸 빼면 무엇이 어떻게 달라지는지"를 쉬운 말로 한 줄씩 붙인다.
**골격 파일(`CLAUDE.md`·`HARNESS.md`·`.claude/` 등)은 고치지 않는다.** 기록용 파일 두 개(`TASKS.md`·`docs/HARNESS-AUDIT.md`)는 5·6단계에서 쓴다.

## 5. 실측 필요 항목을 TASKS.md 로 넘긴다
「실측 필요」로 분류된 것은 `TASKS.md` 「할 일」에 항목으로 남긴다 — 각각 **어떻게 확인하는지(무엇을 돌려 무엇이 보이면 통과인지)** 까지 적는다.
사람이 새 세션·다른 폴더에서 직접 돌려야 하는 것이면 그렇게 명시한다.
`TASKS.md` 가 없으면 `plan-feature` 스킬의 빈 템플릿 형태로 그때 만든다.

**이미 `TASKS.md` 에 같은 항목이 있으면 새로 만들지 말고 그 항목을 갱신한다**(중복 금지).
새 열린 항목을 만들 때는 ID 주석(`<!-- open:이름 -->`)을 `TASKS.md` 항목 줄 끝에 붙이고,
`docs/HARNESS-AUDIT.md` 머리의 `womc:open-checks` 구획에 같은 ID 를 한 줄 더한다.
**조건·확인 방법 전문은 `TASKS.md` 에만 쓴다** — `docs/HARNESS-AUDIT.md` 는 목록 한 줄만 둔다.

## 6. docs/HARNESS-AUDIT.md 에 기록
이번 감사를 **맨 위에** 추가한다(최신이 위). 형식은 고정이다 —
제목줄이 「어느 womc 버전 — 언제 / 어느 Claude Code 버전 기준」이고, 그 아래 절 5개:
「1. 무엇을 확인했나」 · 「2. 뒤집힌 전제」 · 「3. 무엇을 뺐나(근거)」 · 「4. 무엇을 왜 남겼나」 · 「5. 실측 필요」.
파일이 없으면 이 형식으로 새로 만들고, 맨 위 인용문에 「마지막 감사 기준 버전」과 「실측 필요 목록이 어디인지」를 적는다.
지난 기록의 「실측 필요」가 이번에 판명됐으면 그 자리를 「확인됨」으로 고친다.
**기록을 추가할 때마다 맨 위 인용문의 두 값(마지막 감사 기준 버전 · 실측 필요 목록 위치)을 이번 기록 것으로 조건 없이 갱신한다.**
**기록을 추가·수정할 때마다 파일 머리의 `womc:open-checks` 구획도 열린 항목의 현재 상태로 갱신한다** — 닫힌 항목은 그 줄째 지운다. 항목을 닫거나 보류로 내렸으면 `TASKS.md` 쪽 그 항목의 `<!-- open:이름 -->` 주석도 함께 지운다(ID 주석은 열린 `- [ ]` 항목에만 남긴다).
본문 절에는 열린 항목의 조건을 베껴 적지 않는다. `→ 열린 확인 open:xxx (정본: TASKS.md 「할 일」)` 한 줄만 남긴다.

## 7. 다음으로
「뺄 수 있음」이 하나라도 나왔으면, 실제로 걷어내는 일은 이 스킬이 하지 않고 **`plan-feature` 로 넘긴다**고 사용자에게 안내한다
(골격을 줄이는 건 여러 파일이 얽힌 큰 작업이다). 사용자에게 "지금 정리할까요, 기록만 남길까요?"처럼 쉽게 묻는다.
