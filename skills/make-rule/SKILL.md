# 규칙·스킬 만들기

사용자가 "앞으로 ○○하게 해줘" 같이 반복해서 지킬 규칙을 원하거나, "○○할 땐 이렇게 해줘" 같이 반복하는 절차를 남기고 싶어 하면 이 절차를 따른다.
사용자는 코딩 용어(paths, 스코프, 폴더 경로 등)를 모른다고 전제한다. 의도만 듣고, 기술적인 변환은 전부 이 스킬이 한다.

## 0. 무엇을 만들지 먼저 가른다
- **지킬 것**("앞으로 ○○하게 해줘", "자꾸 △△하지 마") → `.claude/rules/` 규칙 파일. 아래 1~3절을 따른다.
- **반복하는 절차·이 프로젝트만의 방법**("○○할 때는 이런 순서로 해줘") → `.claude/skills/<이름>/SKILL.md` 로 만든다. 아래 4절.
- 같은 일을 두 번 이상 했으면 사용자가 말하기 전에 먼저 제안한다. 예: "이거 저번에도 같은 순서로 했어요. 스킬로 남겨 둘까요?"
- 애매하면 한 줄로 되묻는다. 예: "이건 항상 지킬 약속인가요, 아니면 그 작업 할 때 따라갈 순서인가요?"

## 1. 규칙 의도 정리
사용자가 원하는 걸 규칙 한 문장으로 바꿔 보여주고 맞는지 확인한다.
예: "색이랑 간격 제멋대로 바꾸지 마" → "색과 간격은 정해둔 값만 쓴다"
규칙 파일 문장 자체도 짧게 쓴다 — 한 줄에 규칙 하나, 예시는 필요할 때만 하나. (`paths` 없는 규칙은 항상 로드돼 매 세션 토큰을 쓴다.)

## 2. 적용 범위 판단 (핵심)
이 규칙이 프로젝트 어디서 켜져야 하는지 직접 정한다. 사용자에게 폴더 경로를 묻지 않는다.
- 먼저 프로젝트 구조를 살핀다(Glob 등으로 폴더·파일 종류 파악).
- 규칙이 특정 영역에만 해당하면(예: 디자인 규칙 → 스타일/CSS, 저장 규칙 → 데이터 관련 파일) 그 영역만 스코프한다.
- 폴더가 역할별로 안 나뉘어 있으면 파일 종류로 스코프한다(예: 스타일 규칙이면 `**/*.css`).
- 정말 프로젝트 전체에 해당하면(예: "모든 설명은 한국어로") 범위를 전체로 둔다.
- 어느 쪽인지 애매하면 용어 없이 한 줄로 되묻는다.
  예: "이 규칙은 화면 디자인할 때만 지키면 되나요, 아니면 어디서나 지켜야 하나요?"

## 3. 규칙 파일 만들기
`.claude/rules/<알기쉬운이름>.md` 를 만든다. 같은 이름이 있으면 덮어쓰지 말고 알린다.
- 규칙이 **「앞으로 여기는 손대면 안 된다 / 이건 다시 꺼내지 마라」 같은 제약**이면 이름을 `제약-<영역>.md` 로 짓는다. `plan-feature` 가 서브에이전트에 일을 맡길 때 이 이름으로 제약 파일을 찾아 프롬프트에 함께 넣는다 — 이름이 다르면 못 찾는다.
- 이런 제약은 `TASKS.md`(할 일 목록)에 적지 않는다. 할 일은 끝나면 사라지지만 제약은 사라지지 않아, 거기 두면 무한히 쌓이고 관계없는 작업에서도 매번 읽힌다.
- 제약이 **특정 파일 묶음이 아니라 프로젝트 어디에나** 걸리면 `제약-공통.md` 한 파일에 모은다(`paths` 없이 — 항상 켜지므로 짧게 유지한다). 이 파일에는 「사용자가 닫은 것」(안 고른 길·확정된 가정)·「나중에 · 안 할 것」 절을 둔다 — `plan-feature` 가 설계를 마칠 때 그 이름의 절을 찾아 적는다.
- 제약을 적기 전에 `.claude/rules/제약-*.md` 에 같은 내용이 이미 있는지 본다. **한 사실은 한 곳에만 적는다** — 두 곳에 적히면 나중에 어느 쪽이 맞는지 판별할 방법이 없다.

- 특정 영역만 적용이면, 맨 위에 paths 를 적어 그 경로에서만 켜지게 한다:
~~~markdown
---
paths:
  - "<해당 경로>/**"
---
<규칙 문장>
~~~
이렇게 하면 그 경로의 파일을 건드릴 때만 규칙이 켜지고, 다른 작업에선 꺼져 있어 토큰을 아낀다.

- 프로젝트 전체 적용이면, paths 없이 규칙 문장만 적는다(항상 켜진다). 전체 적용은 항상 토큰을 쓰므로, 정말 전역일 때만 이렇게 한다.
~~~markdown
<규칙 문장>
~~~

`.claude/rules/` 안의 파일은 CLAUDE.md 에 따로 import 하지 않아도 자동으로 인식된다.
(paths 가 있으면 그 경로를 건드릴 때, 없으면 항상 켜진다. 서브에이전트에 어떻게 전달되는지는 `CLAUDE.md` 「적극 위임」이 정본이다.)

## 4. 스킬 파일 만들기 (반복 절차일 때)
`.claude/skills/<알기쉬운이름>/SKILL.md` 를 만든다. 같은 이름이 있으면 덮어쓰지 말고 알린다.
frontmatter 는 `name`·`description` 둘이면 충분하다.
~~~markdown
---
name: <폴더와 같은 이름>
description: <언제 쓰는지 — 사용자가 할 법한 말과 상황을 그대로 적는다>
---
# <제목>
<절차를 순서대로. 한 단계 한 줄.>
~~~
- **`description` 에 「언제 쓰는지」를 적어야 모델이 알아서 집는다.** 무엇을 하는지만 적으면 필요한 순간에 안 떠오른다.
- 절차는 사용자가 실제로 한 순서 그대로 적는다 — 추측으로 단계를 늘리지 않는다.
- 스킬 본문이 길어지면 참고 자료는 같은 폴더의 다른 파일로 빼고 SKILL.md 에서 가리킨다(스킬은 필요할 때만 읽힌다).

## 5. 마무리 안내
무엇을 만들었고 언제 켜지는지, 용어 없이 한국어로 짧게 알린다.
예: "디자인 규칙을 만들었어요. 스타일을 손볼 때만 자동으로 적용되고, 다른 작업엔 영향 없습니다."
예: "배포 순서를 스킬로 남겼어요. 다음에 '배포하자'고 하면 이 순서를 알아서 따라갑니다."
