# 변경 이력 (CHANGELOG)

> 끝난 작업의 기록이다. **`TASKS.md` 에 쌓아 두지 않는다** — 한 건이 끝나면 그때그때 이 파일 **맨 위**에 적는다(최신이 위).
> 옛 결정 이유를 찾을 때 보는 곳이 여기다 — 사본은 다른 곳에 없다.
> 각 항목의 형식은 `TASKS.md` 와 같다 — 손댈 파일 · 남긴 것 · 확인 방법.
> 한 줄 요약만 필요하면 이 파일 **맨 아래** 「버전 한 줄 요약 (색인)」을 본다.
> **옛 항목이 가리키는 자리 하나가 바뀌었다**: v2.13.0 이전 항목에 나오는 `PLAN.md` 의 「나중에 / 안 할 것」·「설계 결정 (계속 유효 — 앞으로도 지킨다)」은

## v3.2.0 — `plan-feature` 를 깎았다: 계획 되묻기 폐지 · 「확인 방법」을 계획에서 (2026-08-31)
  - **계기**: 사용자가 `plan-feature` 와 `implement` 를 직접 지목해 셋을 지시했다 — ① 구현 위임에 「확인 방법」을 함께 넘길 것 ·
    ② 계획 되묻기를 없앨 것 · ③ 절 번호와 서브에이전트 이름 지정을 지울 것. v3.0.0 의 「모델을 믿는다 — 하네스는 얇게」를 스킬 본문에 한 번 더 적용한 판이다.
  - **바꾼 것 셋**
    - **① 「확인 방법」이 계획에서 채워져 구현까지 간다.** `TASKS.md` 템플릿의 그 칸 문구를 「어떤 명령·동작으로 확인하나 — 모르면 비워두고 나중에 확인할 때 채운다」 →
      「돌릴 명령 한 줄 + 통과 신호. **계획을 세울 때 채운다. 비워 두지 않는다**」로 바꿨다. 「구현 위임」 절이 그 칸을 그대로 넘기고,
      `agents/implement.md` 는 그것을 입력 계약으로 받아 **구현 뒤 직접 돌린 뒤** 새 출력 칸 「5) 확인 결과」에 통과/실패를 적는다(옛 「5) 주의점」은 6) 으로 내려갔다).
      전에는 확인 방법을 「나중에 확인할 때」 채웠다 — 그래서 다음 세션이 그 항목만 읽고는 무엇으로 확인하는지 알 수 없었다.
    - **② 계획 되묻기를 없앴다.** 「안 고른 길」·「확실하지 않은 가정」을 쉬운 말로 옮겨 **사용자에게 고르게 하던** 절차를 폐지하고,
      메인이 읽고 골라 **한 줄로 알리고 그대로 진행**하는 것으로 바꿨다(새 절 「갈림길은 네가 고른다」).

      다만 **서브에이전트를 늘려 계획을 검사시키지는 않는다** — 5종째 서브에이전트는 여전히 안 만든다.
    - **③ 절 번호(0~7)와 서브에이전트 이름 지정을 지웠다.** 「조사는 `explore`, 설계는 `plan`, 구현은 `implement`」 같은 지정은 항상 로드되는
      `CLAUDE.md` 「적극 위임」에 이미 있다 — 스킬에 또 적으면 한 사실이 두 곳이 된다. 절 제목이 번호에서 이름으로 바뀌었다:

  - **함께 뺀 것 4개 — 모두 `CLAUDE.md` 에 이미 있는 중복이다**: 범위 확인(「안 만들 것」에 걸리는지) · `/code-review` 권유 · 체크포인트 커밋 · 새 세션·`/compact` 권유.
